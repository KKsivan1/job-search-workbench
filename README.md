# 求职工作台

把投递进度、面试安排、准备资料和面试复盘放在一起，让每一次面试都成为下一次准备的起点。

求职工作台是一款面向求职者的个人求职管理与知识积累工具。你可以用它跟踪多个公司的岗位进度，安排笔试与面试，整理自己的项目回答，把真实面试中的问题沉淀为可复习的知识库，也可以借助 AI 将外部面经和学习资料整理成候选学习稿。

它不是招聘信息平台，也不替你投递简历或承诺获得 Offer。它关注的是：当你已经开始求职，如何把分散的事项、资料和经验组织成一套可持续使用的个人工作流。

## 为什么做这个项目？——用 STAR 讲清楚

### S｜场景：求职不只是投简历，更是在管理多个并行任务

同时准备多家公司的面试时，岗位进度可能在表格里，面试时间在聊天记录里，自我介绍和项目材料在不同文档里，面经又收藏在不同平台。临近面试需要来回查找；面试结束后即使写了复盘，也不一定能在下一次准备时用上。

真正的问题不是缺少资料，而是资料与行动没有连起来：不知道今天最该做什么，不容易找到对应材料，也难以看清哪些问题反复没答好。

### T｜目标：让求职者知道进度、找到材料、持续改进

工作台围绕三个目标设计：

- 安排清楚：今天和接下来有哪些笔试、面试、测评、沟通，需要在什么时间完成？
- 准备到位：某个岗位需要看哪些资料，我的自我介绍与项目回答在哪里？
- 经验复用：这次面试问了什么，我哪里没答好，下次应该怎样准备？

适合正在校招、实习招聘或社会招聘中并行跟进多个岗位的人，也适合希望长期积累项目表达、行业知识和面试经验的求职者。已有 Markdown / Obsidian 知识库的人，可以继续使用原有文档，不必把所有内容重新搬到另一套编辑器里。

### A｜方案：围绕“安排—准备—面试—复盘—复练”形成闭环

| 用户的需求 | 工作台提供的能力 | 如何使用 |
| --- | --- | --- |
| 看清各家公司、各岗位走到哪一步 | 投递看板与公司列表；新增、更新岗位，以及删除和恢复 | 按“公司＋岗位”管理，填写阶段、下一步与备注，不把参加过面试等同于通过面试 |
| 不遗漏明天的面试或测评 | 总览日历、分钟级待办、新增与编辑弹窗、完成状态和回收站 | 设置事项类型、日期与具体时间；关联准备文档，点击事项即可进入阅读 |
| 快速找到自我介绍与项目说辞 | 回答库分类、搜索、置顶和 Markdown 预览 | 将常用回答置顶；调整时进入章节编辑，不必直接面对整篇源码 |
| 把真实面试经验留下来 | 面试记录、时间线、复盘阅读与章节编辑 | 整理问题、原回答和候选优化回答，保留上下文，而不只收藏“标准答案” |
| 针对反复暴露的问题练习 | 复练中心、已有跨场次总结入口和总览的最近面试优化点 | 结合复盘制定复练任务，再修正说辞；不是自动给出录用判断 |
| 整理外部面经和知识资料 | 学习入库支持文字、链接与截图，调用服务端 DeepSeek 生成候选 Wiki 草稿 | 提取可读取内容，检查来源与结构，经本人确认后归档到回答库 |

这些模块不是互相独立的收藏夹。例如，一条“明天 14:30 产品经理一面”的待办可以关联准备文档；面试结束后建立复盘；把没有讲清楚的问题变成复练任务，再更新项目回答。

### R｜价值：让准备有入口，让复盘有下一步

项目希望帮助你减少查找与重复整理，把注意力放在理解岗位、讲清经历和修正短板上。一次面试结束后，留下的不只是“面过某家公司”的记录，而是能够继续使用的问题、回答和改进计划。

这是产品希望带来的价值，不是已经验证的录用率或效率提升数据。是否真正有效，可以观察自己是否更少遗漏事项、是否更快找到准备资料，以及反复出现的表达问题是否在复练后得到改善。

## 一个典型使用流程

1. 在投递看板新增公司与岗位，填写已确认的招聘阶段和下一步。
2. 收到面试通知后，新增带日期与时间的待办，关联对应准备文档。
3. 面试前，从待办打开资料；在回答库复习自我介绍、项目经历与相关知识。
4. 面试后，补全面试记录，整理问题、自己的原回答及需要改进的部分。
5. 安排复练，更新回答；外部资料通过学习入库生成草稿，经核验后补充知识库。

## 本地启动

需要 Node.js 24。执行 `npm ci`、`npm run dev`，打开 http://127.0.0.1:3000 。
默认知识库为仓库内的 `wiki/`，只带通用模板和空白面试台账。自定义知识库可设置服务端 `WIKI_ROOT`。新建岗位和面试后由本人确认进度，不推断招聘结果。应用仅监听本机。

## 数据与安全

代码开源不等于数据公开。`data/`、个人 Wiki、日志、备份、账号、环境配置、API Key、构建产物和历史均不进入发布包。添加自己的知识库后，务必重新检查 Git 跟踪范围；不要上传个人 Wiki。默认 `wiki/` 被 Git 忽略，发布包中的模板需首次显式添加。

## 在线使用

不想在本地安装，也可以使用 [求职工作台在线版](https://kaka-d7g5b966o1c26232f-1404740426.tcloudbaseapp.com/autumn-recruitment-hub/)。

在线版支持邮箱验证注册，注册后开通独立个人空间，从通用模板与空白记录开始。在线版暂不开放复练中心、学习入库及大模型调用。此入口暂为开发测试域名，首次访问可能出现平台提示页；正式域名配置完成后会更新链接。本地与在线版的数据不会自动同步。

## 验证与边界

运行 `npm test`、`npx tsc --noEmit`、`npm run lint`。模型草稿须本人核验；部分受限链接和视频无法自动获取正文，不保证自动转写。本地与云端为独立副本，尚无自动双向同步。云端置顶存于当前浏览器。
